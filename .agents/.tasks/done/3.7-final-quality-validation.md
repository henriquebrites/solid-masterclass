## Intent

Depois de 3.1–3.6, cada ferramenta foi validada isoladamente, mas nada confirma que elas funcionam juntas — e `AGENTS.md`, que documenta os comandos de validação do projeto, não reflete os scripts novos (`typecheck`, `test:run`, `test:coverage`, `format:check`).

Depois desta tarefa, todos os comandos de qualidade rodam em sequência sem erro, o CI e os hooks continuam funcionando, e `AGENTS.md` lista os comandos atualizados.

## Criteria

1. Quando `pnpm run lint`, `pnpm run format:check`, `pnpm run typecheck`, `pnpm run build`, `pnpm run test:run` e `pnpm run test:coverage` rodam em sequência localmente, então cada um termina com exit code `0`.
2. Quando `.github/workflows/ci.yml` roda sobre o estado final, então todos os steps (type-check, lint, format check, build, migrations, testes) passam.
3. Quando `.husky/pre-commit` e `.husky/pre-push` rodam (ex.: via um commit/push de teste), então `lint-staged` e `pnpm run test:run` executam conforme configurado, sem mudança de comportamento.
4. Quando `node ./dist/index.js` (a partir do build produzido pelo critério 1) inicia, então ele não lança erro de resolução de módulo.
5. Quando a seção de comandos do `AGENTS.md` é inspecionada, então ela lista `typecheck`, `test:run`, `test:coverage` e `format:check` ao lado dos comandos já existentes.
6. Quando `src/resources/daos/UserDAO.ts` e `UserDAO.test.ts` são inspecionados depois de 3.1–3.6, então nenhum dos dois foi modificado, e rodar `UserDAO.test.ts` continua passando.
