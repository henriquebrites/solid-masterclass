## Intent

Hoje, `package.json:8` (`"test": "vitest"`) roda o Vitest em modo watch, mas `.github/workflows/ci.yml:57` e `.husky/pre-push:3` chamam `pnpm exec vitest run` diretamente, sem passar por nenhum script nomeado. O `AGENTS.md` documenta `pnpm test` como comando de verificação oficial, o que diverge do que CI e hooks realmente executam. Da mesma forma, a checagem de tipos em CI (`.github/workflows/ci.yml:48`, `pnpm exec tsc --noEmit`) não tem script nomeado correspondente — quem quiser reproduzir localmente exatamente o que o CI faz precisa adivinhar o comando ad hoc certo.

Depois desta mudança, `package.json` ganha os scripts nomeados `typecheck` e `test:run`, e CI/hooks passam a invocá-los em vez dos comandos ad hoc — eliminando a divergência entre o que é documentado e o que é executado.

## Criteria

### Scripts nomeados substituem comandos ad hoc

1. Quando `package.json` é inspecionado, então ele contém os scripts `"typecheck": "tsc --noEmit"` e `"test:run": "vitest run"`.
2. Quando `.github/workflows/ci.yml` é inspecionado, então seus steps de type-check e de testes invocam `pnpm run typecheck` e `pnpm run test:run`, não mais `pnpm exec tsc --noEmit`/`pnpm exec vitest run`.
3. Quando `.husky/pre-push` é inspecionado, então ele invoca `pnpm run test:run`, não mais `pnpm exec vitest run`.
4. Quando `pnpm test` roda localmente sem argumentos, então ele continua iniciando o Vitest em modo watch, inalterado.
