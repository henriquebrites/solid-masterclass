# 2.3 — Descoberta de skills e regras no Cursor

Sources:

- https://linear.app/henrique-brites/issue/DEV-9/23-descoberta-de-skills-e-regras-no-cursor - descrição, critérios de aceite, arquivos envolvidos, prioridade e dependência de DEV-8
- https://cursor.com/docs/rules - **binding para o formato de regras**: `.cursor/rules/` aceita apenas arquivos `.mdc` com frontmatter YAML (`description`, `alwaysApply`, `globs`); um `.md` puro é ignorado por não ter frontmatter; `AGENTS.md` na raiz é suportado nativamente; não existe mecanismo nativo de descoberta de diretório de "skills" equivalente a `.claude/skills/`

## Out of scope

- Reorganizar a tabela de diretórios em `AGENTS.md` (assunto de DEV-7) - esta tarefa apenas adiciona uma menção ao Cursor
- Criar symlinks de skills para dentro de `.cursor/rules/` - descartado pela pesquisa: Cursor não descobre diretórios de skills, só `.mdc`/`AGENTS.md`, então um symlink ali não teria efeito e violaria "nenhuma skill duplicada como cópia"
- Instalar ou configurar o Cursor em si - fora do controle deste repositório

## Landing

Toca `.cursor/rules/agents.mdc` (novo), `AGENTS.md` e `CLAUDE.md` (menção ao Cursor). Reutiliza o texto já existente em `CLAUDE.md` sobre a lista de skills e o padrão "fonte única + referência" definido em DEV-8, em vez de duplicá-lo.

- Nenhum one-way door: a escolha de referência textual (em vez de symlink) é reversível a qualquer momento editando `agents.mdc`, e é uma consequência direta e verificada do formato de regras do Cursor, não uma preferência de projeto - portanto não há alternativa viva para registrar como door.

## Checks

### S1 - Diretório de regras do Cursor · 3 arquivos · ~5 KB · ~1k

**C1** - Existe `.cursor/rules/agents.mdc` com extensão `.mdc` (não `.md`), único formato que o Cursor carrega como regra
Proof: `test -f .cursor/rules/agents.mdc`

**C2** - O arquivo de regra contém frontmatter YAML válido reconhecido pelo Cursor (`description` e `alwaysApply`)
Proof: `head -n 1 .cursor/rules/agents.mdc | grep -q '^---$' && grep -q '^alwaysApply:' .cursor/rules/agents.mdc && grep -q '^description:' .cursor/rules/agents.mdc`

**C3** - A regra referencia `AGENTS.md` explicitamente (aplicando as mesmas convenções de organização de arquivos, arquitetura e limites de autonomia ao Cursor)
Proof: `grep -q 'AGENTS.md' .cursor/rules/agents.mdc`

**C4** - A regra expõe as skills ao Cursor por referência textual a `.agents/skills/`, listando as 9 skills atuais, e não por symlink
Proof: `grep -q '\.agents/skills/' .cursor/rules/agents.mdc && for s in commit-message github-readme-generator harness-eval the-judge tlc-discover tlc-implement tlc-plan tlc-spec-driven tlc-spec-lean; do grep -q "$s" .cursor/rules/agents.mdc || echo "MISSING: $s"; done` (sem saída de MISSING = todas presentes)

**C5** - Nenhuma skill foi duplicada como cópia de arquivo dentro de `.cursor/`; se qualquer link existir ali, deve ser symlink, nunca conteúdo próprio
Proof: `! find .cursor -type f -path '*skills*' 2>/dev/null | grep -q .` (nenhum arquivo de skill copiado sob `.cursor/`)
