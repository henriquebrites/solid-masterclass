## Round 1 (commit 933b4e2) — C1 FAIL, blocked

The first `User.test.ts` used `expectTypeOf(...).toEqualTypeOf(...)`, whose proof
(`pnpm exec vitest run src/application/entities/User.test.ts`) only runs the file at runtime,
where `expectTypeOf` is a no-op stripped by esbuild. `tsconfig.json` excludes `**/*.test.ts`
from `tsc`, and Vitest's `--typecheck` mode only scans `**/*.test-d.ts` by default — so no
command the project runs actually type-checked the file. Verified by injecting a wrong field
into the expected type and confirming every available command (`vitest run`, `tsc --noEmit`,
`vitest run --typecheck`) still reported success.

## Fix (commit a04a4c7)

Renamed `User.test.ts` → `User.test-d.ts`; added `test.typecheck.include: ["src/**/*.test-d.ts"]`
to `vitest.config.ts`; added `"test:types": "vitest run --typecheck"` to `package.json`; fixed
the relative import to `./User.js` (required by `moduleResolution: nodenext` once the file was
picked up by `tsc`'s type-check pass).
